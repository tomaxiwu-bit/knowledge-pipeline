# v0.3.0 功能演示脚本（约 2 分 30 秒）

这不是占位宣传片。请只在 FreshRSS、Karakeep、Memos 和本地知识服务都已成功连接后录制，并用自己的测试材料。

| 时间 | 画面 | 旁白 / 操作 |
| --- | --- | --- |
| 0:00–0:15 | 终端：`docker compose up`，随后设置页「本地知识问答服务」显示连接成功 | “知识流水线把桌面工作流和本地智能服务分开运行。正文在 SQLite，向量在 Chroma，模型由本机 Ollama 提供。” |
| 0:15–0:35 | 首页三栏，打开一个 RSS 条目 | “我从 RSS、收藏和速记收集材料；已有流程和凭据仍由桌面端安全管理。” |
| 0:35–0:50 | 阅读页点击「🧠 加入知识库」 | “单篇材料可以立刻入库。若嵌入模型还没准备好，它仍会进入全文索引，而不是悄悄失败。” |
| 0:50–1:15 | 进入「知识问答」，点击「同步已连接来源」 | “批量同步会将已连接来源分块，更新 SQLite FTS 和 Chroma 索引。” |
| 1:15–1:50 | 提问一个确实能由材料回答的问题 | “提问时系统融合关键词和语义召回，再进行本地重排。回答不脱离材料：每个来源都以证据卡返回。” |
| 1:50–2:10 | 点击两张证据卡，回到原始阅读页 | “我可以回到原文核对证据，而不是只相信模型表述。” |
| 2:10–2:30 | 打开探究线，把一条材料标为证据，展示当前判断和下一步 | “最终目标不是积累聊天记录，而是把证据转化为可复查的判断与下一步行动。” |

## 录制检查

- 录屏分辨率至少 1440×900，隐藏 API Key、Token、个人 RSS 标题和终端环境变量。
- 在问答前显示至少 3 个来源，提问必须有可见的证据卡。
- 录制后，在 README 的「演示视频」段落填写视频地址、录制日期、测试的模型名称和应用版本。
- 如运行在检索降级模式，必须在旁白中说明“本地模型不可用”，不要把它剪成生成式问答演示。
